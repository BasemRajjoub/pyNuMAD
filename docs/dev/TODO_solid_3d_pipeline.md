# TODO — Full 3D Solid Blade Pipeline

Tracking doc for the end-to-end 3D solid composite blade pipeline in
the `pce-patches` fork. Captures **what currently works**, **what's
known not to work**, **how to pick it up later**, and the **ordered

- [`solid_mesh_quality_wall.md`](solid_mesh_quality_wall.md) — bug
  traces from the ANSYS-writer integration work.
- [`CHANGELOG.md`](../../CHANGELOG.md) — commit-level history of
  every change on the branch.

## TL;DR — what we have right now

**Full 3D solid composite blade pipeline works end-to-end on the
bundled BAR0 fixture:**

1. Read windIO YAML → `Blade`.
2. `get_solid_mesh(blade, layerNumEls=[1,1,1], elementSize=0.5)` →
   clean 3D solid mesh: 24 696 nodes, 16 653 hex/wedge elements,
   1 080 sections, **0 bad-Jacobian elements**.
3. Write to either ANSYS APDL (`.mac`) **or** Abaqus (`.inp`) with
   one function call (`write_ansys_solid_general` /
   `write_solid_general`). Decks are cross-validated equivalent
   (Phase 4 tests — 11/11 pass).
4. Run in ANSYS R2023 → exit 0, **tip deflection 1.67 m** for a
   1 000 N tip load (physically reasonable for a 100 m flexible
   composite blade). End-to-end ANSYS solve verified
   (`test_solid_solver_run.py` — passes).

The branch with this work: `feat/ansys-solid-writer`. Currently
11 commits; all on origin.

## What's been done (by area)

### Writers

- **`write_ansys_solid_general(fileName, blade, bladeMesh)`** in
  [`src/pynumad/analysis/ansys/write.py`](../../src/pynumad/analysis/ansys/write.py).
  APDL counterpart of the existing Abaqus
  [`write_solid_general`](../../src/pynumad/analysis/abaqus/write.py).
  SOLID185 with KEYOPT(2)=2 enhanced strain, per-section CSKP fiber
  CSYS, ESEL+EMODIF MAT/ESYS assignment, clamped-root BCs, adhesive
  bondline via the existing `_write_ansys_adhesive` helper.
- **`solidMeshFromShell` kwargs**: three new knobs control the
  three-stage mesh-quality treatment (see next section).

### Mesh-quality fix (bug #1 — resolved)

`solidMeshFromShell` now applies the industry-standard treatment in
order (HyperMesh / ANSYS Workbench Sweep / Cubit Sweep / Pointwise
T-Rex / Mesquite style):

1. **Laplacian smoothing of per-node averaged normals** before
   extrusion (`n_normal_smoothing_iter=2`).
2. **Per-node adaptive layer-thickness clamping** during extrusion
   (`layer_thickness_cap_factor=0.7`): cap each layer offset to
   `α · min(incident shell-edge length)`.
3. **Post-extrusion targeted untangling** (`untangle_max_iter=30`,
   see new
   [`mesh_tools.untangle_solid_mesh`](../../src/pynumad/mesh_gen/mesh_tools.py)):
   Knupp-style top-corner-toward-bottom-corner pull with
   neighbour-preservation.

| Stage | Bad elements | Rate |
|---|---|---|
| legacy (no treatment) | 94 / 16 653 | 0.564 % |
| + normal smoothing | 28 / 16 653 | 0.168 % |
| + adaptive thickness clamp | 8 / 16 653 | 0.048 % |
| + untangle (final) | **0 / 16 653** | **0.000 %** |

Visualisation:
[`docs/dev/figs/solid_mesh_fix_stages.{pdf,png,preview.png}`](figs/)
(generated by
[`scripts/plot_solid_mesh_fix_stages.py`](../../scripts/plot_solid_mesh_fix_stages.py)).

Side effect: `test_all_jacobians_positive` and
`test_all_element_volumes_positive` were xfail against the legacy
extruder; they now strict-pass.

## What's known NOT to work yet

### Bug #4 — `layerNumEls=[2,2,2]` IndexError

`get_solid_mesh(blade, layerNumEls=[2,2,2], 0.5)` crashes in
`tie_2_sets_constraints` with
`IndexError: index N is out of bounds for axis 0 with size N`. Means
the BAR0 solid mesh currently only builds at the default
`layerNumEls=[1,1,1]`. Two xfail tests pin it in CI:
- `test_element_count_scales_with_layer_count`
- `test_node_count_grows_with_layer_count`

Bug already documented at
[`solid_mesh_quality_wall.md`§Bug 4`](solid_mesh_quality_wall.md).

### Non-BAR0 blades — not validated

The three-stage mesh fix is parameter-agnostic and uses no
BAR0-specific constants, but it's only **been exercised on BAR0** in
CI. For IEA-22 (large public blade) or custom blades, the defaults
might or might not need tuning. The IEA-22 YAML is wired into the
test suite via the `PYNUMAD_IEA22_YAML` env var pattern — easy to
extend the test suite once we want this proof.

### `PIVCHK,OFF` workaround in Phase 5

The ANSYS pivot check is disabled in the Phase 5 deck because thin
TE bricks have nodes with near-zero local stiffness in some
direction. The solve completes and the global QoI (tip deflection)
is meaningful, but ill-conditioned DOF displacements may be noisy.
Removing this workaround requires TE-aware shell remeshing (next
step #4 below) — a bigger change to `shell_mesh_general`.

   and their statuses.

### Check current state
```bash
cd pyNuMAD
git checkout feat/ansys-solid-writer  # or whatever branch we're on
PATH="$PATH:/home/$USER/.local/bin" ~/.pixi/bin/pixi run -- python -m pytest \
    src/pynumad/tests/test_shell_to_solid_expansion.py \
    src/pynumad/tests/test_ansys_solid_writer.py \
    src/pynumad/tests/test_solid_cross_validation.py \
    -n 4
# Expected: 27 + 16 + 11 = 54 passed, 2 xfailed (bug #4)
```

### Sanity check the pipeline manually
```python
from pynumad.objects.blade import Blade
from pynumad.mesh_gen.mesh_gen import get_solid_mesh
from pynumad.mesh_gen.mesh_tools import check_all_jacobians
from pynumad.analysis.ansys.write import write_ansys_solid_general
from pynumad.analysis.abaqus.write import write_solid_general

blade = Blade('src/pynumad/tests/test_data/blades/blade.yaml')
mesh = get_solid_mesh(blade, [1,1,1], 0.5)
assert len(check_all_jacobians(mesh['nodes'], mesh['elements'])) == 0
write_ansys_solid_general('blade.mac', blade, mesh)
# For Abaqus, the dict needs a 'materials' key — see
# tests/test_solid_cross_validation.py:_build_mesh_dict_for_abaqus
```

## Backlog — ordered by ROI

### 1. Open PR + merge `feat/ansys-solid-writer` to default branch
**Effort:** 30 min. **Blocks:** everything downstream.
`gh pr create -B <default> -H feat/ansys-solid-writer` (or use the
GitHub URL printed at last push).

### 2. Fix bug #4 — `layerNumEls=[2,2,2]` IndexError
**Effort:** 1 day. **Blocks:** through-thickness refinement studies.
Already has a reproducer + diagnosis in
[`solid_mesh_quality_wall.md`§Bug 4`](solid_mesh_quality_wall.md).
The off-by-one is in
[`mesh_tools.py:606-714`](../../src/pynumad/mesh_gen/mesh_tools.py)
`tie_2_sets_constraints`. Likely fix: `tgtNdCrd` is sized to shell
node count but `elements` use solid-node indices that exceed it
after extrusion — needs to be re-sized.

### 3. Generalise / validate on IEA-22 (and one custom blade)
**Effort:** 1-2 days. **Blocks:** confidence claim "works for any
blade".
Extend `test_shell_to_solid_expansion.py` and the Phase 5 ANSYS-run
test to optionally include IEA-22 (via `PYNUMAD_IEA22_YAML` env
var). Run, then:
- check the bad-Jacobian count stays at 0 (or close);
- if not, sweep `layer_thickness_cap_factor` to find a working
  value for IEA-22 and document the regime;
- confirm ANSYS solves end-to-end.

### 4. Convergence study — BAR0 ANSYS vs Abaqus tip deflection across mesh sizes
**Effort:** 1 day. **Blocks:** the "main test" originally specified
(cross-solver convergence).
Add a parametrised `@slow @integration` test that builds the BAR0
solid mesh at `elementSize ∈ {0.5, 0.3, 0.2, 0.1}`, runs ANSYS for
each (and Abaqus if available — needs an `abaqus` key in
`software_paths.json`), and asserts that the tip-deflection
convergence rate is reasonable. Demonstrates the writer produces a
self-consistent deck across mesh refinement.

### 5. Replace `PIVCHK,OFF` workaround via TE-aware shell remeshing
**Effort:** ~1 week. **Blocks:** production-quality stress recovery
in the thin-TE region.
Currently `_relax_ansys_robustness_settings` in Phase 5 sets
`SHPP,WARN,ALL` and `PIVCHK,OFF`. Proper fix: in
`shell_mesh_general`, coarsen or merge shell elements at the
trailing edge so the local in-plane aspect ratios stay below ~5:1.
The geometric trigger is already understood (HP_TE_FLAT panels with
~0.49 m × 0.03 m shell quads); the fix lives upstream of the
extruder, not in it.

### 6. IEA-22 production run + paper figures
**Effort:** when ready. **Blocks:** nothing inside this fork — this
is when the pipeline gets used for actual research output.
Generate a full solid IEA-22 mesh, run a real load case (DLC-1.x
loads via OpenFAST), extract stress / displacement, plot.
